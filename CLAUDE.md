# Пиксилиус

Песочница «падающего песка» на canvas: клеточная симуляция материалов, жидкостей и газов с теплом, ветром, химией и жителями. Чистый JS в браузере, без сборки, без зависимостей и без npm.

## Запуск и проверка

- Запуск: `node tools/serve.js` → http://localhost:8080 (или конфигурация `pixilius` в `.claude/launch.json`). Сервер отдаёт файлы с `Cache-Control: no-store`.
- `node tools/check.js` — самопроверка без браузера: согласованность таблицы элементов, полнота `swapFields`, прогон сцены (исключения, NaN, мусорные типы, состав долей), отмена и сохранение побайтно, замер мс на `step()` при 576x324.
- `node tools/compare.js [ref] [шагов]` — побайтное сравнение поведения рабочей копии с коммитом (по умолчанию `HEAD`): одно и то же зерно `Math.random`, одна и та же сцена. **После рефакторинга обязан выдать OK.** При намеренной смене поведения он показывает, с какого шага и в каких полях началось расхождение.
- Стенд (`tools/harness.js`) грузит все скрипты из массива `files` в `index.html` до `js/render.js`. Сцена и воздействия заданы в `buildScene`/`poke`. Новую механику стоит добавить в сцену, чтобы `compare`/`check` её покрывали.
- Изменение, заметное глазу (рендер, UI, ввод), проверяй ещё и в браузере.

## Устройство

Скрипты обычные (не ES-модули): все имена верхнего уровня глобальные и общие между файлами. Порядок подключения задаёт массив `files` в `index.html`. Загрузчик там добавляет `?v=` против кэша, его не убирать. **Новый файл надо вписать в этот массив**, и его место в порядке важно.

```
js/data/elements.js     EL (id), CAT, ELEMENTS (свойства), ELEMENT_ORDER (палитра), TECH_ELEMENTS,
                        предикаты isStructural / isAnchor / isAirtight / isHeatInsulator / isOxide ...
js/data/composition.js  система долей: SOL_PARTS=10, виды P_*, точки кипения/замерзания, solGet/solWith...,
                        семейства isSolutionFamily / isVaporFamily / hasComposition, LIQUID_PHASE
js/data/oxides.js       линейки окисления камня/металла/земли (OXIDE_LINE, цвета, хрупкость)
js/sim/core.js          class Sim: поля мира, PARTICLE_FIELDS, spawn/clearCell/swap/swapFields,
                        step() (порядок кадра), updateCell, react() — диспетчер реакций по типу
js/sim/stability.js     устойчивость твёрдых тел (computeStability) и балки — второй слой this.beam
js/sim/wind.js          сетка ветра, диффузия, толчок ветром (tryWindPush, shiftChain), кисть давления
js/sim/heat.js          температура: диффузия/остывание (updateTemp), кисть температуры
js/sim/movement.js      движение сыпучего/жидкости/газа/огня, вытеснение жидкости тонущими телами
js/sim/reactions.js     горение, лава, лёд, песок, соль, вода, пустота, клонер, влажность земли
js/sim/composition.js   механика долей: смешивание, стягивание пустоты, кипение/конденсация/замерзание
js/sim/chemistry.js     кислота, реагент, ржавление, выделение газов, кислотный остаток
js/sim/oxides.js        стадии окисла, хрупкость, кислотостойкость, прорастание окисла
js/sim/human.js         человек: обзор, страх, память запретов, ходьба, смерть
js/sim/colonist.js      колонист (в палитре нет, оставлен ради старых сохранений)
js/sim/painting.js      setCell / stampBrush / stampLine / floodFill
js/sim/persistence.js   snapshot/restore (отмена) и serialize/deserialize (файл .pixsav)
js/render.js            Renderer: цвет клетки, отладочные режимы 1/2/3, лупа, контур кисти
js/input.js             InputController: мышь/клавиши, режимы кисти, undo/redo
js/main.js              создание Sim/Renderer/Input, панель и палитра, игровой цикл (timeScale)
```

**Методы Sim разложены по файлам.** В каждом `js/sim/*.js`, кроме core, объявлен класс-контейнер (`class SimHuman { ... }`), а в конце стоит `extendSim(SimHuman)`: она переносит методы в `Sim.prototype`. Внутри это обычные методы Sim с обычным `this`. Если одно имя метода объявлено в двух файлах, `extendSim` бросает ошибку. Новый метод клади в файл своей подсистемы, новую подсистему выноси в новый файл по тому же образцу.

### Кадр (`Sim.step`)

`computeStability` → `updateBeams` → `updateWind` → `updateTemp` → снимок ветра на кадр (`windVXFrame`) → общий бросок `_windRoll` → `computeDebrisWindChance` → `computeLiquidEscape` → обход клеток **снизу вверх**, с чередованием направления строки по чётности кадра. Для каждой клетки: `react()` (реакция по типу), затем движение по категории (`updatePowder`/`updateLiquid`/`updateGas`/огонь; осыпавшееся твёрдое с `stability===0` падает как сыпучее). `moved[i]=1` помечает клетку, которая в этом кадре уже ходила.

### Состояние клетки

Всё хранится в typed-массивах длиной `w*h` с индексом `i = y*w + x`. Поля, которые переживают кадр, перечислены в `PARTICLE_FIELDS` (core.js): `type, life, extra, shade, temp, moisture, sol, beam, colonistHomeX/Y`. Отмена, сохранение и `clear()` работают строго по этому списку.

`life` и `extra` у каждого элемента означают своё:

| элемент | life | extra |
|---|---|---|
| FIRE | кадров до угасания | 1 = от дерева (оставит золу) |
| SMOKE | кадров жизни | — |
| OILFILM | — | направление единственной связи (0↑ 1→ 2↓ 3←) |
| OXIDE*, METAL_OXIDE*, EARTH_OXIDE | — | стадия окисла (см. `oxideStage`) |
| ACID_RESIDUE | — | уровень 1..4 (с 5 — реагент) |
| HUMAN | личный номер → память в `_humans` | 1 = мёртв |
| COLONIST | единиц груза | материал груза |
| CLONE | — | запомненный элемент |
| EARTH / WET_EARTH | счётчик кадров тика влажности | — |
| газ VAPOR с маслом | срок до выпадения масла | — |

Прочее:
- `sol` — состав жидкости или газа системы долей: 10 долей по 4 бита на вид, включая пустоту `P_VOID`. Есть у всех клеток, для которых `hasComposition(type)` верно, у остальных равен 0. Меняется только через `setComposition()`: она сама подбирает элемент по составу (чистая вода, раствор, пар, смешанный газ...).
- `beam` — второй слой, балка. Её нет в `type`, для жидкостей, газов, сыпучего и людей её просто не существует. Держит только твёрдое (`stabId`).
- `temp` принадлежит частице и едет вместе с ней. `spawn()` прибавляет к температуре места собственную температуру элемента (`baseTemp`/`DEFAULT_BASE_TEMP`), источники тепла ставят `heatSource`.
- Ветер (`windVX/VY`) — грубая сетка `airCell=4`, он не входит ни в отмену, ни в сохранение.

## Чек-листы

**Новый элемент**
1. `EL.X` в `data/elements.js`: следующий свободный id, строго < 64, иначе сломаются таблицы по id.
2. Запись в `ELEMENTS` (`id, name, cat, color, density, flammable` и нужные опции: `maxStability/toughness`, `meltPoint/meltChance/meltsInto`, `boilPoint`, `dispersion`, `heatSource`, `baseTemp`, `acidImmune/acidSlow`, `burnChance/burnLife`).
3. Если он нужен в палитре — в `ELEMENT_ORDER`. Если это техника — ещё и в `TECH_ELEMENTS`.
4. Предикаты по смыслу: `isStructural`, `isAnchor`, `isAirtight`, `isHeatInsulator`, семейства долей в `data/composition.js`, реакции людей `humanDeadly`/`humanDanger`.
5. Своё поведение: метод в файле подсистемы плюс `case` в `Sim.react()` (core.js). Начальные `life/extra` — в `spawn()`.
6. Если цвет зависит от состояния, а не только от `ELEMENTS[id].color`, — `Renderer.cellColor`.
7. Добавить в сцену `tools/harness.js`, затем `node tools/check.js`.

**Новое поле клетки**
1. Завести typed-массив в конструкторе Sim.
2. Вписать его в `PARTICLE_FIELDS`, указав `empty` и `moves`.
3. Если `moves: true` — добавить обмен в `swapFields` вручную: это горячий путь, цикл по списку там дорог. `check.js` падает, если его забыли.
4. Поле появится и в отмене, и в сохранении само. Старые файлы без него получат `empty`.

**Новая подсистема или механика**: новый `js/sim/<имя>.js` по образцу существующих, вписать в `files` в `index.html` после `core.js`, константы настройки держать в начале файла с комментарием.

## Правила кода

- Комментарии на русском, и объясняют они **почему**, включая историю: какой баг был, какая просьба пользователя за этим стоит. Так уже написан весь код, и новое пишется так же. Устаревший комментарий правится вместе с кодом.
- Тонкие места, на которых уже ломались, записаны в комментариях рядом. Перед правкой прочитай комментарий у функции.
- **Производительность**: обход клеток — это ~187 тыс. клеток на кадр. В коде, который вызывается на каждую клетку:
  - никаких выделений памяти (массивов, объектов, замыканий);
  - никаких `Map` и вызовов цепочек функций там, где хватает плоской таблицы по id (пример — `OXIDE_FRAIL_FROM`, `IS_GASLIKE`, `LIQUID_PHASE`);
  - дорогое делается не каждый кадр, а по броску вероятности или с периодом (`RUST_TICK_CHANCE`, `HUMAN_SCAN_PERIOD`).
  
  Замер — последняя строка `node tools/check.js`.
- Движение частицы — только через `swap()` (обмен плюс возмущение ветра) или `swapFields()`, когда одно логическое движение складывается из цепочки обменов. После хода ставь `moved[цель] = 1`. Руками поля не копировать: так уже терялись температура и состав.
- `spawn()` создаёт свежую частицу (сброс `extra`/`life`/`sol`, своя температура). Чтобы сменить тип, сохранив частицу (температуру и оттенок), ставят `type` напрямую, как делают `setComposition`/`setOxideStage`.
- Ветро-зависимые решения берут общий на кадр `_windRoll` и снимок `getWindVX/VY`, а не `Math.random()` на клетку: иначе цельные тела рвутся на части.
- Вероятности заданы «в кадр». Общая скорость времени — `sim.timeScale` в `main.js`, она меняет число вызовов `step()` за кадр. Внутрь механик её не встраивать.
- Сообщения коммитов на русском, короткой фразой о сути, как в `git log`.
